---
description: 从 Splan 文档生成下一条任务的执行提示词（只读）
---
使用 skill 工具加载 `splan`。加载后自报“规划AI”；本命令由规划AI 执行，执行AI 不运行。执行AI 回报固定 7 段式（结论 / 改动清单 / 原理与机制 / 验证 / 行为变化 / §5 记录 / 遗留与风险），不写下一步。

参数：`$ARGUMENTS` = `[<任务ID>] [--doc <路径>]`。任务 ID 在前，`--doc` 可选。未传 `--doc` 时按 SKILL.md「文件位置」定位；多文档命中列出候选并询问，不猜。

步骤：

1. 定位文档并读 §0、§1、§2、§3 相关小节、§4。
2. 选择任务：给了任务 ID 就用它；否则取 §1 第一条未完成且无阻塞的任务（P0 优先）。旧格式没有 §1 时，按出现顺序取全文第一条 `- [ ]`，并提醒迁移。
3. 若 §3 方案与任务摘要不一致，先复述差异；冲突记 C，不覆盖用户在 §3 的编辑。
4. 只输出一个可直接复制的执行提示词（代码块），**必须包含**：
   - `规划文档：<绝对路径>`
   - `必读：§0 机制登记、§2 契约、§3 方案（<任务相关小节>）`
   - 任务原文 + ID
   - `需求：R#`
   - 产出：文件 / 仓库路径
   - `验证手段：<命令 → 期望 / 人工：步骤 → 判定>`
   - `机制：<复用 X / 新建 D#>`
   - 边界：不做什么
   - 分支：仅当用户明确要求时，基于当前分支新建（或切换到）`<type>/<T#-#>-<任务简称>`（type ∈ feature / bugfix / docs / refactor / chore）；未指定则留在当前分支；dirty / 非 git 先停并报告；不自动 merge / push
   - 事实源优先级：代码 / 测试 > 仓库 README、AGENTS > 文档 §0
   - DoD：机器可判的完成条件
   - 回报：固定 7 段式（≤15 行 / 300 字）——1. 结论：做了什么、是否通过；2. 改动清单：文件 + 改了什么；3. 原理与机制：为什么这么做、机制、取舍、替代方案（代码改动必填，纯文档可省略）；4. 验证：命令 / 人工步骤 + 结果；5. 行为变化：用户可见的前后差异；6. §5 记录：一行可直接粘贴的记录；7. 遗留与风险：未完成、已知偏差、后续注意；不写下一步；不改规划文档；不 commit / push；可读性要强
5. 不改任何文件、不执行任务；不 commit / push。如果 §1 为空，直接说明并建议 `/splan-check`。
