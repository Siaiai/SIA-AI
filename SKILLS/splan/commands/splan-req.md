---
description: 随时新增需求 / 假设（Splan 唯一需求入口）
---
使用 skill 工具加载 `splan`。加载后自报“规划AI”。

参数：`$ARGUMENTS` = `<需求> [--doc <路径>] [--fast]`。主对象（需求）在前；`--doc` 可选；`--fast` 跳过阶段 1 的方案讨论，但仍做查重 / 冲突检查。

步骤（默认两阶段）：

1. 定位文档；找不到提示先 `/splan-new`。
2. 扫描：§0 需求登记（R）、§1 任务池（T）、§4 D/C、§3 方案。
3. 查重：按目标 / 验收 / 范围 / 机制比对现有 R/T。重复 → 按 D12 提议合并到最早 R，被并 R 标取消；先列方案等确认，**不静默合并**。
4. 查冲突：与现有 R/T/D/§3 冲突时，列冲突点与取舍；等用户确认后再落文档。

**阶段 1（默认，只讨论）**

- 给 1–3 个方案：目标 / 范围 / 不做什么 / 验收 / 机制 / 影响 / 取舍
- 不写文档、不分配 R、不建任务、不跑 lint
- 等用户确认；未确认前保持只读

**阶段 2（确认后分配 R / 任务 / §3）**

1. 分配下一个 R 号，**永不复用**。
2. 写 §3 方案 + 任务 + C（如适用）；文档已有任务时追加 C：`类型=新增`、`需求=R#`。
3. 清晰 → `R# 状态=待做`，拆任务（标 `需求：R#`、`机制：复用 X / 新建 D#`）；不清晰 → `R# 状态=待澄清` + 探索任务（时盒 + 产出=结论 + 停止条件）。
4. 关联检查：关联 R#；会引入新机制先立 D。
5. 若传 `--doc <外部笔记>`：按 `obsidian.md` 读入，登记 R + `文档` 列；未传时行为不变；笔记缺失不猜，提示补。
6. 更新 §0 看板 / 最后更新，跑 lint（-Strict），回复末尾给文档更新回执。
7. 输出下一条任务的执行提示词。

`--fast`：跳过阶段 1，直接进入阶段 2，但仍先做查重 / 冲突检查并报告；有重复 / 冲突仍需等确认，不静默处理。

角色例外：需求 intake 可问「选哪个方案」；执行阶段不问「要不要我来干」。

不改查重 / 冲突逻辑；不 commit / push；提交只在 `/splan-done` 按 D15 默认判断。
